Part I: Concepts Review

Why renv + Docker?

The Reproducibility Problem:

  • Your code works on your machine
  • Collaborator gets different results (or errors)
  • Six months later, packages have updated and code breaks

Solution: Two layers of reproducibility

Tool What it locks Analogy
renv R package versions Recipe ingredients list
Docker R version, OS, system libraries The entire kitchen

renv: Package Version Control

renv::init()      # Start tracking packages
renv::snapshot()  # Save current package versions to renv.lock
renv::restore()   # Install packages from renv.lock

The renv.lock file records exact versions:

{
  "Packages": {
    "dplyr": {
      "Package": "dplyr",
      "Version": "1.1.4",
      "Source": "Repository"
    }
  }
}

Docker: Environment Containerization

A Docker image packages everything needed to run your analysis:

  • Operating system (e.g., Ubuntu)
  • R version (e.g., R 4.4.0)
  • System libraries (e.g., libcurl, libxml2)
  • Your R packages (via renv)

A container is a running instance of an image.

docker build -t myimage .     # Build image from Dockerfile
docker run myimage            # Run a container

Part VI: Create Dockerfile

Step 13: Understanding the Dockerfile

A Dockerfile is a recipe for building a Docker image. Our Dockerfile will:

  1. Start from a base R image (rocker/r-ver)
  2. Install system dependencies
  3. Copy renv files
  4. Restore packages from renv.lock
  5. Set up the working directory

Step 14: Create Dockerfile

DO THIS: Create a new file called Dockerfile (no extension)

file.create("Dockerfile")
file.edit("Dockerfile")

Step 15: Add Dockerfile Contents

DO THIS: Copy this content into your Dockerfile

FROM rocker/r-ver:4.4.0

# Install system dependencies
RUN apt-get update && apt-get install -y \
    libcurl4-openssl-dev \
    libssl-dev \
    libxml2-dev \
    libfontconfig1-dev \
    libharfbuzz-dev \
    libfribidi-dev \
    libfreetype6-dev \
    libpng-dev \
    libtiff5-dev \
    libjpeg-dev \
    && rm -rf /var/lib/apt/lists/*

# Set working directory
WORKDIR /workspace

# Install renv
RUN R -e "install.packages('renv', repos='https://cloud.r-project.org')"

# Copy renv files
COPY renv.lock renv.lock
COPY renv/activate.R renv/activate.R
COPY .Rprofile .Rprofile

# Restore packages
RUN R -e "renv::restore()"

# Default command
CMD ["/bin/bash"]

Save the file.

Step 16: Create .dockerignore

DO THIS: Create a .dockerignore file to exclude unnecessary files

writeLines(c(
  "analysis/data/raw_data/*",
  "analysis/figures/*",
  ".git",
  ".Rhistory",
  ".RData",
  "*.html",
  "*.pdf"
), ".dockerignore")

This keeps your image small and avoids including sensitive data.

Part VII: Build and Test Docker Image

Step 17: Build Docker Image

DO THIS: Open Terminal in your project directory and build the image

docker build -t yourusername/adni-analysis:v1 .

Replace yourusername with your Docker Hub username.

This may take 10-15 minutes the first time as packages are installed.

Checkpoint: Build completes with “Successfully built” message

Step 18: Test the Container

DO THIS: Run the container interactively

docker run --rm -it -v "$(pwd):/workspace" yourusername/adni-analysis:v1

This mounts your local files into the container.

Step 19: Verify Inside Container

DO THIS: Inside the container, start R and test

R
library(tidyverse)
library(survival)
sessionInfo()

Checkpoint: All packages load, versions match renv.lock

Type quit() then exit to leave the container.

Troubleshooting Reference

“Docker daemon not running”

Start Docker Desktop application.

“renv::restore() fails in Docker”

Check that renv.lock and renv/activate.R are properly copied.

“Permission denied” during docker build

On Mac/Linux:

sudo docker build -t myimage .

“Package installation fails in Docker”

Add missing system dependencies to the Dockerfile apt-get install line.
