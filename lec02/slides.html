Question: Have you ever tried to reproduce someone else’s analysis or your own work from a year ago? What challenges did you encounter?

Answer: “When I tried to reproduce my thesis advisor’s analysis from three years ago, I discovered the code required packages that no longer existed in their original form, the data had been reorganized, and several manual steps were undocumented. It took two weeks to recreate what should have been a simple rerun.”

What is Reproducible Research?

  • Reproducibility: Same data + same code = same results
  • Replicability: New data + same methods = consistent findings
  • Transparency: Complete documentation of analytical decisions

Note

Reproducibility is the minimum standard for credible scientific research. Replicability builds scientific knowledge.

  • Distinguish between reproducibility and replicability
  • Reproducibility is technically achievable with proper practices
  • Replicability depends on underlying scientific phenomena
  • Both are essential for building trustworthy biostatistical research

Question: Why is reproducibility particularly important in biostatistics compared to other fields?

Answer: “Biostatistical analyses directly inform clinical decisions, drug approvals, and public health policy. A non-reproducible analysis could lead to ineffective treatments being approved or effective ones being rejected. The stakes are literally life and death.”

The Reproducibility Crisis

  • 2016 Nature survey: 70% of researchers failed to reproduce others’ work
  • 50% failed to reproduce their own work
  • Causes include:
    • Incomplete documentation
    • Software version changes
    • Undocumented data preprocessing
    • “Works on my machine” syndrome
  • The reproducibility crisis affects all scientific fields
  • Biostatistics has a special responsibility to lead by example
  • Our methods and code are integral to research conclusions
  • Proper practices prevent embarrassing retractions and wasted resources

Question: What are the professional consequences of publishing non-reproducible research?

Answer: “Beyond retractions, which damage careers and institutions, non-reproducible work wastes research funding when others cannot build on it. In clinical contexts, it can delay effective treatments or expose patients to ineffective ones. It erodes public trust in science.”

Components of Reproducible Analysis

  1. Data Management: Raw data preservation, clear provenance
  2. Code Organization: Modular, well-documented scripts
  3. Environment Capture: Package versions, system dependencies
  4. Documentation: README files, analysis narratives
  5. Version Control: Complete history of changes
project/
├── data/
│   ├── raw/           # Never modify
│   └── processed/     # Generated by code
├── R/                 # Analysis functions
├── analysis/          # Scripts and reports
├── output/            # Results, figures
└── README.md          # Project documentation
  • Each component addresses specific reproducibility failures
  • Data management prevents “which version did I use?” problems
  • Code organization enables others to understand your work
  • Environment capture addresses software dependency issues
  • Version control provides complete audit trail

Question: Which of these components do you think is most commonly neglected in biostatistical practice?

Answer: “Environment capture is often overlooked. People assume their code will work because they documented it, but then package updates break functionality. I once spent days debugging an analysis that failed simply because dplyr had changed how it handled grouped operations.”

Literate Programming

  • Combine narrative, code, and results in single documents
  • R Markdown and Quarto enable literate programming in R
  • Benefits:
    • Analysis and documentation stay synchronized
    • Results update automatically when data changes
    • Complete transparency of analytical process
# Example: Analysis and explanation together
library(palmerpenguins)

# Calculate mean body mass by species
penguins |>
  group_by(species) |>
  summarise(
    mean_mass = mean(body_mass_g, na.rm = TRUE),
    sd_mass = sd(body_mass_g, na.rm = TRUE)
  )
  • Literate programming was proposed by Donald Knuth in 1984
  • R Markdown and Quarto are modern implementations
  • Documents serve as both analysis scripts and reports
  • Updates propagate automatically through the document

Question: How does literate programming change the way you think about documenting statistical analyses?

Answer: “Instead of writing code first and documentation later, I now write the narrative of my analysis and embed code within it. This forces me to explain my reasoning as I work, which often catches logical errors early and produces better documentation as a natural byproduct.”

Package Management with renv

  • renv captures exact package versions used in a project
  • Creates isolated, reproducible R environments
  • Key commands:
    • renv::init() - Initialize renv for a project
    • renv::snapshot() - Record current package versions
    • renv::restore() - Restore recorded package versions
# Initialize renv in a new project
renv::init()

# After installing packages, capture the state
renv::snapshot()

# On a new machine, restore the exact environment
renv::restore()
  • renv solves the “works on my machine” problem
  • Each project has its own package library
  • The renv.lock file records exact versions
  • Collaborators can recreate your exact environment

Question: What problems does renv solve that simply documenting package versions in a README does not?

Answer: “README documentation requires manual installation and hopes versions are still available. renv automates restoration and handles dependency chains. When package A requires version 2.0 of package B, but package C requires version 1.5, renv manages these conflicts automatically.”

Version Control with Git

  • Track all changes to code and documents over time
  • Collaborate without overwriting each other’s work
  • Revert to any previous state of the project
  • Essential Git concepts:
    • Repository: Project folder tracked by Git
    • Commit: Snapshot of changes with description
    • Branch: Parallel version for development
    • Merge: Combine branches together
  • Git is the standard version control system in data science
  • GitHub and GitLab provide cloud hosting and collaboration features
  • Version control is expected in both academic and industry positions
  • We will cover Git and GitHub in detail in the next lecture

Question: How does version control support reproducibility beyond simply backing up your files?

Answer: “Version control provides a complete audit trail of analytical decisions. When a reviewer asks why you chose a particular model specification, you can show exactly when and why that decision was made. It’s documentation through history rather than separate narrative.”

Best Practices for Collaborative Biostatistics

  1. Never modify raw data - All transformations in code
  2. Use relative paths - Projects should be portable
  3. Document dependencies - Use renv or similar tools
  4. Write modular code - Functions over scripts
  5. Include a README - Project overview and instructions
  6. Use version control - Git for all projects
  7. Review each other’s code - Catch errors early

Note

These practices are not extra work - they prevent rework, enable collaboration, and build trust in your analyses.

  • Each practice addresses specific collaboration failures
  • Raw data preservation enables reanalysis from scratch
  • Relative paths allow projects to move between machines
  • Code review catches errors and spreads knowledge

Question: Which of these practices would have the biggest impact on your current workflow?

Answer: “For me, writing modular code as functions rather than monolithic scripts would be transformative. Currently, when I need to change something, I have to hunt through hundreds of lines. Functions with clear inputs and outputs would make changes localized and testing possible.”

Team Science in Biostatistics

  • Biostatisticians work on collaborative research teams
  • Essential team science skills:
    • Clear communication of statistical concepts
    • Documentation that non-statisticians can understand
    • Reproducible workflows that others can verify
    • Responsive collaboration and revision
  • Reference the team science skills paper for deeper reading
  • Biostatisticians bridge quantitative methods and domain science
  • Communication skills are as important as technical skills
  • Reproducible practices enable effective collaboration

Question: How does reproducible research practice improve collaboration with non-statistician colleagues?

Answer: “When I share a reproducible analysis with clinical collaborators, they can see exactly what was done to their data. This builds trust and enables meaningful discussions about analytical choices. They may not read the code, but knowing it exists and is transparent changes the dynamic.”

The rrtools Package

REFERENCE ONLY

  • rrtools provides templates for reproducible research projects
  • Creates standardized project structure
  • Integrates with R package development tools
# Create a new research compendium
rrtools::use_compendium("myproject")

# Add analysis folder structure
rrtools::use_analysis()

# Creates:
# analysis/
# ├── paper/
# ├── figures/
# ├── data/
# └── templates/

Question: When would you choose rrtools over a simpler project structure?

Answer: “rrtools is ideal when the goal is a published paper with a complete research compendium. For exploratory analyses or internal reports, a simpler structure suffices. The key is matching project organization to project goals and audience.”
